### Трассировка (trace)

<aside>
💡

Когда вы пишете UI тесты, частенько они будут падать, и бывает сходу сложно понять почему. Мы будем сохранять трассировку — это инструмент, который записывает все действия, которые выполняются в тесте:

- **Скриншоты** : Фотографии экрана на каждом шаге
- **DOM-дерево** : Структура HTML-страницы
- **Исходный код теста** : Код, который выполнялся
- **Промежуточные состояния приложения** : Как страница выглядела на каждом этапе

С помощью Trace можно "прокрутить" выполнение теста назад и увидеть, что именно пошло не так

</aside>

### **Создание Универсальных Методов в `Tools` для работы с файловой системой**

### **Импортируем библиотеку `pathlib` и** `datetime`

```python
from pathlib import Path
from datetime import datetime
```

<aside>
💡

**`pathlib`** — это модуль Python, который предоставляет удобный объектно-ориентированный интерфейс для работы с путями к файлам и папкам
Вместо того чтобы конкатенировать строки (например, **`"folder" + "/" + "file.txt"`** используя os.path.realpath), мы можем использовать оператор **`/`** для объединения путей, благодаря чему код удобочитаем, нагляден и вообще конфетка

Создадим класс **`Tools`**, который будет содержать два статических метода:

</aside>

```python
class Tools:
    @staticmethod
    def project_dir():
        """
        Возвращает корневую директорию проекта.
        Предполагается, что текущий файл находится в поддиректории `common`.
        """
        return Path(__file__).parent.parent

    @staticmethod
    def files_dir(nested_directory: str = None, filename: str = None):
        """
        Возвращает путь к директории `files` (или её поддиректории).
        Если директория не существует, она создается.
        Если указан `filename`, возвращает полный путь к файлу.
        """
        files_path = Tools.project_dir() / "files"
        if nested_directory:
            files_path = files_path / nested_directory
        files_path.mkdir(parents=True, exist_ok=True)
        
        if filename:
            return files_path / filename
        return files_path

    @staticmethod
    def get_timestamp():
        """
        Возвращает текущую временную метку в формате YYYY-MM-DD_HH-MM-SS.
        """
        return datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
```

### Метод `def project_dir`

<aside>
⚙

- Этот метод возвращает путь к корневой директории проекта.

**Как работает:**

- **`Path(__file__)`**: Получает путь к текущему файлу (тому, где написан этот код)
- **`.parent`**: Поднимается на один уровень выше (в родительскую директорию)
- **`.parent.parent`**: Поднимается ещё на один уровень выше, чтобы получить корневую директорию проекта
- Корневая директория проекта часто используется как базовый путь для хранения файлов (например, логов, трассировок и т.д.)
</aside>

---

### Метод `files_dir(nested_directory)`

<aside>
⚙

- Этот метод возвращает путь к директории **`files`** (или её поддиректории). Если директория не существует, она создаётся.
</aside>

<aside>
❓

**Как работает?** 

- **`Tools.project_dir() / "files"`**: Формирует путь к директории **`files`** внутри корневой директории проекта.
- **`if nested_directory`**: Если передана вложенная директория, добавляет её к пути
- **`mkdir(parents=True, exist_ok=True)`**:
    - **`parents=True`**: Создаёт все необходимые родительские директории
    - **`exist_ok=True`**: Не выбрасывает ошибку, если директория уже существует
- `if filename` - позволяет вернуть еще путь с названием файла. Пригодится для сохранения трассировки
</aside>

<aside>
❓

**Зачем это нужно?**  

Этот метод позволяет легко создавать и использовать директории для хранения тестовых файлов, трассировок, логов или скриншотов и тд.

</aside>

---

### **Метод `get_timestamp`**

<aside>
❓

**Что делает?** 

 Этот метод возвращает текущую дату и время в формате **`YYYY-MM-DD_HH-MM-SS`**. Например: **`2023-10-05_14-30-45`**

</aside>

<aside>
❓

**Как работает?** 

- **`datetime.now()`**: Получает текущую дату и время
- **`.strftime("%Y-%m-%d_%H-%M-%S")`**: Форматирует дату и время в удобный для чтения формат
</aside>

<aside>
❓

**Зачем это нужно?** 

Временная метка позволяет создавать уникальные имена файлов, что исключает перезапись старых файлов при повторных запусках тестов

</aside>

### **Обновление Фикстуры для Trace**

Обновляем фикстуру которая создает `context`:

```python
@pytest.fixture(scope="function")
def context(browser):
    context = browser.new_context()
    context.tracing.start(screenshots=True, snapshots=True, sources=True)
    context.set_default_timeout(DEFAULT_UI_TIMEOUT)
    yield context
    log_name = f"trace_{Tools.get_timestamp()}.zip"
    trace_path = Tools.files_dir('playwright_trace', log_name)
    context.tracing.stop(path=trace_path)
    context.close()
```

<aside>
1️⃣

`context.tracing.start(screenshots=True, snapshots=True, sources=True)`

Начинает запись Trace.

**Параметры** :

- **`screenshots=True`**: Записывает скриншоты.
- **`snapshots=True`**: Записывает DOM-дерево.
- **`sources=True`**: Записывает исходный код теста.
</aside>

<aside>
2️⃣

`log_name = f"trace_{Tools.get_timestamp()}.zip"`

Имя файла будет уникальным благодаря временной метке. Например: trace_2025-02-27_03-30-45.zip

</aside>

<aside>
3️⃣

`trace_path = Tools.files_dir('playwright_trace', log_name)`

Используем метод `files_dir`, чтобы объединить путь к директории logs и имя файла

</aside>

<aside>
4️⃣

 `context.tracing.stop(path=trace_path)`

Останавливает запись Trace и сохраняет её в файл

передаем полный путь к файлу в метод **`stop`**

</aside>
