### **Что такое Pydantic и зачем он нужен?**

<aside>
⚙

Pydantic — это библиотека на Python, которая помогает работать с данными: валидировать их, преобразовывать и управлять ими. Она особенно полезна, когда нужно убедиться, что данные соответствуют определённым правилам или структуре. Pydantic часто используется в веб-приложениях (например, с FastAPI ( для полноценных мок сервисов. но об этом позже)), а также может быть полезен в тестах.

</aside>

<aside>
❓

### Зачем Pydantic в тестах?

- Помогает убедиться, что данные соответствуют ожидаемой структуре.
- Упрощает работу с данными, автоматически преобразуя их в нужные типы.
- Делает тесты более читаемыми и надёжными.
- Как делать?

</aside>

```python
from pydantic import BaseModel
from venv import logger

class User(BaseModel):  # Создается класс User с помощью BaseModel от pydantic и указывается
    name: str       # что имя должно быть строкой
    age: int        # возраст должен быть числом
    adult: bool     # поле совершенолетие должно быть булевым значением

def get_user():  # функция get_user возвращает обьект dict с следущими полями
    return {
        "name": "Alice",
        "age": 25,
        "adult": "true"
    }

def test_user_data():
    user = User(**get_user())  # Проверяем возможность конвертации данных и соответствия типов данных с помощью Pydantic
    assert user.name == "Alice"  # Возможность дополнительных проверок 
    logger.info(f"{user.name=} {user.age=} {user.adult=}")  # а также возможность удобного взаимодействия 

```

### 🔍 Подробное объяснение работы кода с Pydantic

<aside>
⚙

В этом коде мы используем библиотеку **Pydantic** для валидации и преобразования данных. Давай разберем его пошагово с точки зрения **Python**.

</aside>

### **1. Определение модели данных с помощью Pydantic**

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str       # Имя должно быть строкой
    age: int        # Возраст должен быть числом
    adult: bool     # Поле "совершеннолетие" должно быть булевым значением

```

<aside>
❓

### Что здесь происходит?

- `class User(BaseModel)`:
    - Мы создаем **класс** `User`, который **наследуется** от `BaseModel` из Pydantic
    - `BaseModel` автоматически добавляет функциональность проверки и преобразования данных
- Аннотация типов `name: str, age: int, adult: bool`:
    - Это говорит Python (и Pydantic), что `name` всегда должно быть строкой, `age` – целым числом, а `adult` – булевым значением (`True` или `False`).
    - **Pydantic сам конвертирует значения в нужные типы**, если это возможно!
</aside>

---

### **2. Функция, которая возвращает данные в виде словаря**

```python
def get_user():
    return {
        "name": "Alice",
        "age": 25,
        "adult": "true"
    }
```

<aside>
❓

### Что здесь происходит?

- Эта функция возвращает **словарь (`dict`)** с данными пользователя.
- **Обрати внимание** на `"adult": "true"` – это строка, а не `True` (булево значение).
- По правилам `User`, `adult` должен быть `bool`, но передан **неправильный** тип данных.

💡 **Pydantic автоматически исправит это при создании объекта!**

</aside>

---

### **3. Используем Pydantic для валидации и преобразования данных**

```python
def test_user_data():
    user = User(**get_user())  # Передаём данные в модель Pydantic

```

<aside>
❓

### Что здесь происходит?

- `User(**get_user())` – создаём **экземпляр класса `User`**.
- `**get_user()` – **распаковываем словарь** и передаём значения в `User`:
    
    ```python
    User(name="Alice", age=25, adult="true")
    
    ```
    
- **Pydantic автоматически:**
    1. **Преобразует** `"true"` в `True`, так как `adult` должен быть `bool`
    2. **Проверит**, что `age` – это число (если бы мы передали строку `"25"`, он превратил бы её в `int(25)`)
    3. **Создаст объект `User`**, где всё соответствует правильным типам!
</aside>

---

### **4. Проверяем корректность данных**

```python
    assert user.name == "Alice"
```

<aside>
➖

- Это обычный `assert`, который проверяет, что `user.name` действительно `"Alice"`.
- Если бы данные были некорректны, `Pydantic` выбросил бы ошибку **ещё при создании объекта**.
</aside>

---

### **5. Логируем данные**

```python
    logger.info(f"{user.name=} {user.age=} {user.adult=}")
```

<aside>
❓

### Что здесь происходит?

- `f"{user.name=} {user.age=} {user.adult=}"` – это **f-строка с раскрытием переменных**.
- Выведет:
    
    ```
    user.name='Alice' user.age=25 user.adult=True
    
    ```
    
- **Демонстрирует, что Pydantic исправил "true" → `True`.**
</aside>

## **Вывод: Как это работает?**

1. **Определяем модель данных** с ожидаемыми типами (`BaseModel`).
2. **Передаём словарь в Pydantic**, который **автоматически проверяет и преобразует** данные.
3. **Если что-то не так, Pydantic выбросит ошибку**.
4. **В итоге у нас чистые, проверенные данные в объекте `User`**.
</aside>

</aside>

<aside>
➖

`Optional`  и `Default` **-**  позволяет указывать необязательные поля и значения по умолчанию.

</aside>

<aside>
➖

`Enum`  **-** поддерживает Enum для ограничения возможных значений поля, а также поддерживает работу с вложенными моделями

</aside>

<aside>
💡

Pydantic позволяет легко конвертировать модели в JSON и обратно.

</aside>

- Пример на основе класса Product отображающий основные возможности:
    
    ```python
    # CinescopeFork\Modul_4\PydanticExamples\test_pydantic.py
    from typing import Optional
    from pydantic import BaseModel, Field
    from enum import Enum
    from venv import logger
    
    class ProductType(str, Enum): 
        NEW = "new"
        PREVIOUS_USE = "previous_use"
    
    class Manufacturer(BaseModel):
        name: str
        city: Optional[str] = None
        street: Optional[str] = None
        
    class Product(BaseModel):
    		# поле name может иметь длину в диапазоне от 3 до 50 символов и является строкой
        name: str = Field(..., min_length=3, max_length=50, description="Название продукта")
        # поле price должно быть больше 0
        price: float = Field(..., gt=0, description="Цена продукта")
        # поле in_stock принимает булево значение и установится по умолчанию = False
        in_stock: bool = Field(default=False, description="Есть ли в наличии")
        # поле colorдолжно быть строкой и принимает значение "black" по умолчанию
        color: str = "black"  
        # поле year не обязательное. можно не указывать при создании обьекта
        year: Optional[int] = None
        # поле product принимает тип Enum (может содержать только 1 из его значений)
        product: ProductType
        # поле manufacturer принимает тип другой BaseModel
        manufacturer: Manufacturer
    
    def test_product():
        # Пример создания обьекта + в поле price передаём строку вместо числа
        product = Product(name="Laptop", price="999.99", product=ProductType.NEW, manufacturer=Manufacturer(name="MSI"))
        logger.info(f"{product=}")
        # Output: product=Product(name='Laptop', price=999.99, in_stock=False, color='black', year=None, product=<ProductType.NEW: 'new'>, manufacturer=Manufacturer(name='MSI', city=None, street=None))
    
        # Пример конвертации обьекта в json
        json_data = product.model_dump_json(exclude_unset=True)
        logger.info(f"{json_data=}")
        # Output: json_data='{"name":"Laptop","price":999.99,"product":"new","manufacturer":{"name":"MSI"}}'
    
        # Пример конвертации json в обьект
        new_product = Product.model_validate_json(json_data)
        logger.info(f"{new_product=}")
        # Output: new_product=Product(name='Laptop', price=999.99, in_stock=False, color='black', year=None, product=<ProductType.NEW: 'new'>, manufacturer=Manufacturer(name='MSI', city=None, street=None))
    ```

    Pydantic автоматически конвертирует данные в нужные типы, если это возможно.

### 🔍 Подробное объяснение ключевых компонентов Pydantic

<aside>
💡

В этом разделе мы рассмотрим ключевые механизмы **Pydantic** и как они помогают при работе с данными. **Pydantic** обеспечивает валидацию, преобразование и структурирование данных, что делает код более **чистым**, **надежным** и **удобным в тестировании**.

</aside>

### **1. `BaseModel` — основа всех моделей в Pydantic**

```python
from pydantic import BaseModel

class Product(BaseModel):
    name: str
    price: float

```

<aside>
❓

**Что делает `BaseModel`?**

- **Автоматически валидирует данные** при создании объекта.
- **Конвертирует типы** (например, `"999.99"` → `999.99`).
- **Позволяет сериализовать и десериализовать** данные (например, в JSON).
</aside>

- **Пример использования:**
    
    ```python
    product = Product(name="Laptop", price="999.99")
    print(product)
    # Product(name='Laptop', price=999.99)
    ```
    
    <aside>
    ➖
    
    - **Pydantic автоматически преобразовал строку `"999.99"` в `float`!**
    - Если бы вместо цены передали `"сто долларов"`, **Pydantic выбросил бы ошибку**.
    </aside>

### **2. `Field` — настройка полей**

<aside>
💡

`Field` позволяет задавать **ограничения и описания** для полей.

</aside>

```python
from pydantic import BaseModel, Field

class Product(BaseModel):
    name: str = Field(..., min_length=3, max_length=50, description="Название продукта")
    price: float = Field(..., gt=0, description="Цена продукта")

```

<aside>
❓

**Что здесь происходит?**

- `min_length=3, max_length=50` — имя продукта должно быть от 3 до 50 символов.
- `gt=0` — цена должна быть **больше 0**.
- `description="..."` — описание, которое будет в **JSON Schema**.
</aside>

### Эллипсис или `…`

В Pydantic символ **`...`** (эллипсис) используется как значение по умолчанию для обязательных полей. Это специальный объект в Python, который в контексте Pydantic указывает, что поле **должно быть обязательно заполнено** при создании экземпляра модели

### **Разберем подробнее:**

1. **Что означает `...`?**
    - **`...`** — это сокращение для объекта **`Ellipsis`**, который является встроенным объектом в Python
    - В Pydantic он используется для обозначения того, что поле является **обязательным** (т.е. его значение должно быть предоставлено при создании экземпляра модели)
2. **Зачем использовать `...` вместо значения по умолчанию?**
    - Если вы хотите, чтобы поле было обязательным, но не хотите задавать для него значение по умолчанию, вы используете **`...`**.
    - Например:Здесь **`name`** — обязательное поле, и при создании экземпляра модели **`Product`** вы должны предоставить значение для **`name`**
        
        ```python
        name: str = Field(..., min_length=3)
        ```
        
3. **Как это работает?**
    - Когда Pydantic видит **`...`** в качестве значения по умолчанию, он проверяет, что значение для этого поля было явно передано при создании экземпляра модели
    - Если значение не передано, Pydantic вызывает ошибку валидации
4. **Пример использования:**
    
    ```python
    from pydantic import BaseModel, Field
    
    class Product(BaseModel):
    name: str = Field(..., min_length=3, max_length=50, description="Название продукта")
    price: float = Field(..., gt=0, description="Цена продукта")
    
    # Попытка создать экземпляр без обязательных полей вызовет ошибку
    try:
    product = Product()
    except Exception as e:
    print(e)  # Output: "field required" для обоих полей
    
    # Корректное создание экземпляра
    product = Product(name="Laptop", price=1000.0)
    
    print(product)
    
    # Output: name='Laptop' price=1000.0
    ```
    
5. **Альтернатива `...`:**
    - Если надо сделать поле необязательным, можно использовать значение по умолчанию, например:
        
        Здесь поле **`name`** будет необязательным, и если значение не передано, оно примет значение **`"Unknown"`**
        
        ```python
        name: str = Field(default="Unknown", min_length=3)
        ```
        
6. **Почему не просто `None`?**
    - Использование **`None`** в качестве значения по умолчанию делает поле необязательным, но позволяет ему принимать значение **`None`**. Если нужно, чтобы поле было обязательным, но не имело значения по умолчанию, **`...`** — это правильный выбор

### **Пример с необязательным полем:**

```python
class Product(BaseModel):
name: str = Field(..., min_length=3)  # Обязательное поле
price: float = Field(default=0.0, ge=0)  # Необязательное поле с дефолтным значением
```

### **Подытожим:**

- **`...`** используется для обозначения обязательных полей в Pydantic
- Если поле необязательное, можно использовать значение по умолчанию (например, **`None`** или другое значение)

### **7. Обратное преобразование (из JSON в объект)**

### **1. Как работают кастомные валидаторы в Pydantic?**

<aside>
💡

В Pydantic есть специальный **декоратор** `@field_validator`, который позволяет задать **проверку для конкретного поля**.

</aside>

```python
from pydantic import BaseModel, Field, field_validator

class Card(BaseModel):
    pan: str = Field(..., min_length=16, max_length=16, description="Номер карты")

    @field_validator("pan")
    def check_pan(cls, value: str) -> str:
        """Проверяем, что PAN (номер карты) состоит только из цифр"""
        if not value.isdigit():
            raise ValueError("PAN должен содержать только цифры")
        return value
```

<aside>
❓

**Что здесь происходит?**

1. **Поле `pan`** – должно быть **ровно 16 символов** (`min_length=16, max_length=16`).
2. **Декоратор `@field_validator("pan")`** – добавляет проверку **после** стандартной валидации.
3. **Метод `check_pan`**:
    - Проверяет, что `pan` состоит **только из цифр**.
    - Если есть **буквы или другие символы**, выбрасывает `ValueError`.
</aside>

- **Пример использования:**
    
    ```python
    Card(pan="1234567890123456")  #  Всё ок
    Card(pan="1234abcd90123456")  #  Ошибка: PAN должен содержать только цифры
    ```

### **3. Проверка нескольких полей одновременно**

<aside>
💡

Если валидация должна зависеть от **нескольких полей**, используется `@model_validator`.

</aside>

<aside>
🛠

**Пример: проверяем, что `cvc` у карты `Visa` должен быть именно 3 цифры, а у `Amex` – 4 цифры.**

</aside>

```python
from pydantic import BaseModel, Field, model_validator
from enum import Enum

class CardType(str, Enum):
    VISA = "Visa"
    AMEX = "American Express"

class Card(BaseModel):
    pan: str = Field(..., min_length=16, max_length=16)
    cvc: str = Field(..., min_length=3, max_length=4)
    card_type: CardType

    @model_validator(mode="before")
    def check_cvc_for_card_type(cls, values):
        """
        Проверяем, что:
        - У карт VISA cvc == 3 цифры
        - У карт AMEX cvc == 4 цифры
        """
        if values["card_type"] == CardType.VISA and len(values["cvc"]) != 3:
            raise ValueError("CVC для VISA должен быть 3 цифры")
        if values["card_type"] == CardType.AMEX and len(values["cvc"]) != 4:
            raise ValueError("CVC для AMEX должен быть 4 цифры")
        return values

```

- **Пример использования:**
    
    ```python
    Card(pan="1234567890123456", cvc="123", card_type=CardType.VISA)  #  Всё ок
    Card(pan="1234567890123456", cvc="1234", card_type=CardType.VISA)  #  Ошибка: CVC для VISA должен быть 3 цифры
    Card(pan="1234567890123456", cvc="1234", card_type=CardType.AMEX)  #  Всё ок
    ```


<aside>

### **Что такое сериализация и десериализация?**

Сериализация и десериализация – это процессы преобразования данных между различными форматами.

- **Сериализация** – это **преобразование объекта в строку** или **байтовый формат**, чтобы его можно было передавать по сети, сохранять в файл или базу данных
- **Десериализация** – это **обратное преобразование** строки или байтового формата обратно в объект
</aside>

---

<aside>
💭

## **Простыми словами**

*Сериализация* – это как упаковать объект в коробку, чтобы его можно было переслать другому человеку

*Десериализация* – это как открыть коробку и достать из нее объект

</aside>

### **Пример сериализации и десериализации в Python**

<aside>
🛠

В Python для сериализации часто используется **JSON**.

</aside>

```python
import json

# Объект Python (словарь)
user = {
    "name": "Alice",
    "age": 25,
    "email": "alice@example.com"
}

# Сериализация (Python → JSON)
json_data = json.dumps(user)
print(json_data)
# Вывод: {"name": "Alice", "age": 25, "email": "alice@example.com"}

# Десериализация (JSON → Python)
user_obj = json.loads(json_data)
print(user_obj["name"])  # Вывод: Alice

```

<aside>
❓

**Что здесь произошло?**

- `json.dumps()` – превратил **словарь** в **JSON-строку**
- `json.loads()` – превратил **JSON-строку** обратно в **словарь**
</aside>

### Что-такое лямбда функция? И что она делает в коде

```python
def register_user(self, user_data: TestUser):
        """Регистрирует нового пользователя"""
        return self.requester.send_request("POST", "/register", data=json.loads(user_data.model_dump_json(exclude_unset=True)))
```

при вызове метода user_data.model_dump_json происходит сериализация обьекта модели в JSON (преобразовании сложных типов данных) ,  стандартный сериализатор Pydantic не всегда может корректно обработать такие типы данных. В частности, он не знает, как преобразовать Enum в строку, если Enum находится внутри списка.

поэтому  вданном случае мы вынуждены добавить кастомынй сериализотор
внутрь нашего Enum

```python
class Config:
json_encoders = {
Roles: lambda v: v.value  # Преобразуем Enum в строку
}
```

давайте рассмотрим как рабоатет данный код.

Все сериализоторы должны быть обьявлены в блоке Config
json_encoders:

Это специальный словарь, который указывает Pydantic, как сериализовать определённые типы данных.

Ключом является тип данных (в нашем случае Roles), а значением — функция, которая преобразует этот тип данных в строку.

так как тело функции очень простое мы можем использовать анонимную лямбда функцию
`lambda v: v.value:`

- 👉🏼 Детали лямбды
    
    **Как работает `lambda v: v.value`?**
    
    ```python
    
    json_encoders = {
        Roles: lambda v: v.value
    }
    
    ```
    
    - `v` — это экземпляр `Roles`, например `Roles.USER`.
    - `v.value` — это **строковое представление**, которое указано в `Enum`:
        
        ```python
        
        class Roles(str, Enum):
            USER = "USER"
            ADMIN = "ADMIN"
        
        ```
        
    - Если мы передаём `Roles.USER`, то:
        
        ```python
        
        lambda v: v.value  # v = Roles.USER
        # Возвращает "USER"
        
        ```
        
- 🔍 **Лямбда-функции в Python: как они работают на низком уровне?**
    
    **❗ Используйте `lambda`, когда это оправдано, но не забывайте про `def`, если код становится сложнее!**
    
    Они работают **так же, как `def`**, но без имени и с ограниченной областью памяти.
    
    Лямбда-функции в Python — **это не магия, а просто способ сократить код**.
    
    ## **🚀 Вывод**
    
    ---
    
    | Ситуация | Что использовать? |
    | --- | --- |
    | Простая одноразовая функция | `lambda` |
    | Функция с `if`, `for`, `while` | `def` |
    | Функция в `map()`, `filter()` | `lambda` |
    | Функция с аннотациями типов | `def` |
    | Функция должна быть читаемой | `def` |
    
    ## **🛠 Что лучше: `lambda` или `def`?**
    
    ---
    
    ### ❌ **Минусы**
    
    ✘ Если сложная логика — **лучше `def`**
    
    ✘ Лямбда сложнее отлаживать (`__name__ = "<lambda>"`)
    
    ✘ Нельзя использовать **аннотации типов**
    
    ### 
    
    ✔ Сразу удаляется после выполнения
    
    ✔ Удобна для **быстрого использования в `map()`, `filter()`**
    
    ✔ **Короткая запись**
    
    ### ✅ **Плюсы**
    
    ## **📌 Итог: Плюсы и минусы `lambda`**
    
    ---
    
    - `__closure__` показывает замороженные переменные внутри `lambda`.
    
    ```python
    print(times3.__closure__[0].cell_contents)  # 3
    
    ```
    
    Её хранит **объект лямбды** (см. `__closure__`):
    
    **Переменная `n` не исчезает, даже если `multiplier()` завершил работу!**
    
    💡 **Важно!**
    
    - `times3(10)` использует это замыкание, перемножая `10 * 3`.
    - `multiplier(3)` создаёт **замыкание**, где `n = 3` сохраняется в памяти.
    
    📌 **Как это работает в памяти?**
    
    ```python
    def multiplier(n):
        return lambda x: x * n  # Лямбда запоминает `n`
    
    times3 = multiplier(3)
    print(times3(10))  # 30
    
    ```
    
    ### 5️⃣ **Как работает `lambda` с замыканиями (closures)?**
    
    ---
    
    - `def` же **остается в памяти** даже после выполнения.
    - Если мы используем `lambda` внутри `map()`, то **она не занимает память после выполнения**.
    
    🔍 **Почему это важно?**
    
    1. Как только `map()` завершает работу, `lambda` **уничтожается** (Garbage Collector её удаляет).
    2. `map()` вызывает её для каждого элемента `numbers`.
    3. Python создаёт `lambda x: x ** 2` в памяти.
    
    📌 **Как это работает?**
    
    ```python
    numbers = [1, 2, 3, 4]
    squared = list(map(lambda x: x ** 2, numbers))
    print(squared)  # [1, 4, 9, 16]
    
    ```
    
    Когда `lambda` передаётся в `map()`, `filter()`, `sorted()`, она **создаётся и тут же удаляется** после использования.
    
    ### 4️⃣ **Как `lambda` ведёт себя с `map` и `filter`?**
    
    ---
    
    - `lambda` **сама по себе не создаёт глобальную запись**, но если её присвоить переменной, то она становится доступной.
    - `def` **создаёт запись в `globals()`**, поэтому функция доступна по имени.
    
    📌 **Вывод:**
    
    ```python
    print(globals()["square_def"])
    # <function square_def at 0x7f8b7e10b550>
    
    print(globals()["square_lambda"])
    # KeyError: 'square_lambda' (только если не присвоить переменной)
    
    ```
    
    🔍 **Как увидеть это в `globals()`?**
    
    - `lambda` создаёт **анонимную функцию**, которая не хранит своё имя.
    - `def` создаёт **именованную функцию**, которая остаётся доступной в `globals()`.
    
    ```python
    print(square_def.__name__)  # square_def
    print(square_lambda.__name__)  # <lambda>
    
    ```
    
    📌 **Как Python обрабатывает это?**
    
    ```python
    def square_def(x):
        return x * x
    
    square_lambda = lambda x: x * x
    
    ```
    
    Рассмотрим обычную и лямбда-функцию с точки зрения Python:
    
    ### 3️⃣ **Разница между `lambda` и `def` в памяти**
    
    ---
    
    ✅ **Правда**: Разницы нет, потому что Python **всё равно создаёт объект функции** и хранит его в памяти.
    
    ❌ **Ошибка многих новичков**: Думают, что `lambda` быстрее, потому что она без имени.
    
    Python хранит все функции (обычные и `lambda`) в **куче (heap memory)**.
    
    ### 2️⃣ **Где хранится лямбда в памяти?**
    
    ---
    
    - Это аналогично созданию функции через `def`, но без имени.
    - Он не хранит **имя** функции (`<lambda>` — просто техническое обозначение).
    - Python создаёт **объект функции** (`<function <lambda> at ...>`) в памяти.
    
    📌 **Что тут происходит?**
    
    ```python
    square_lambda = lambda x: x * x
    print(square_lambda)
    # <function <lambda> at 0x7f8b7e10b550>
    
    ```
    
    Когда интерпретатор Python встречает `lambda`, он **не создаёт именованную функцию**, а **возвращает объект функции в памяти**.
    
    ### 1️⃣ **Как Python интерпретирует лямбда?**
    
    ## **🔍 Как работает лямбда-функция внутри Python?**
    
    ---
    
    ```python
    # Обычная функция
    def square(x):
        return x * x
    
    # Эквивалентная лямбда-функция
    square_lambda = lambda x: x * x
    
    print(square(5))  # 25
    print(square_lambda(5))  # 25
    
    ```
    
    ### **📌 Пример лямбда-функции**
    
    **Лямбда-функция** — это **анонимная (безымянная) функция**, которую можно объявить в одну строку. Она используется для **простых выражений**, когда нет смысла писать `def`.
    

лямбда функция - это функция, которая принимает значение Enum (v) и возвращает его строковое представление через атрибут v.value.

Например, если Roles.USER имеет значение "USER", то v.value вернёт строку "USER".

данный код аналогичен использованию метода

```python
def get_val(val: Roles):
    return val.value
```

```python
    def log_request_and_response(self, response):
        """
        Логгирование запросов и ответов. Настройки логгирования описаны в pytest.ini
        Преобразует вывод в curl-like (-H хэдэеры), (-d тело)

        :param response: Объект response получаемый из метода "send_request"
        """
        try:
            request = response.request
            headers = " \\\n".join([f"-H '{header}: {value}'" for header, value in request.headers.items()])
            full_test_name = f"pytest {os.environ.get('PYTEST_CURRENT_TEST', '').replace(' (call)', '')}"

            body = ""
            if hasattr(request, 'body') and request.body is not None:
                if isinstance(request.body, bytes):
                    body = request.body.decode('utf-8')
                elif isinstance(request.body, str):
                    body = request.body
                body = f"-d '{body}' \n" if body != '{}' else ''

            self.logger.info(
                f"{GREEN}{full_test_name}{RESET}\n"
                f"curl -X {request.method} '{request.url}' \\\n"
                f"{headers} \\\n"
                f"{body}"
            )

            response_status = response.status_code
            is_success = response.ok
            response_data = response.text
            if not is_success:
                self.logger.info(f"\tRESPONSE:"
                                 f"\nSTATUS_CODE: {RED}{response_status}{RESET}"
                                 f"\nDATA: {RED}{response_data}{RESET}")
        except Exception as e:
            self.logger.info(f"\nLogging went wrong: {type(e)} - {e}")

```

Цвета можно положить в константы:
