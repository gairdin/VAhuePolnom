### Первый запуск

Перед тем как приступать, предлагаю вам сделать новый проект или организовать код так, чтобы он был обособленный. Заниматься мы будем на внешнем ресурсе, а после задания будут подразумевать повторение пройденного материала и дз на кинескопе

Соответственно если это новый проект, не забудьте так же установить pytest

```python
from playwright.sync_api import sync_playwright
```

<aside>
☝

Эта строка говорит Python, что нам нужен специальный инструмент (функция **`sync_playwright`**) из библиотеки Playwright для работы с браузером. **`sync_api`** означает, что мы будем использовать синхронный (последовательный) стиль программирования

Для того, чтобы нам запустить браузер, сделать первые шаги, необходимо написать следующий код:

</aside>

```python
from playwright.sync_api import sync_playwright
import time

# Создаем экземпляр Playwright и запускаем его
playwright = sync_playwright().start()

# Далее, используя объект playwright, можно запускать браузер и работать с ним
browser = playwright.chromium.launch(headless=False)
page = browser.new_page()
page.goto('https://demoqa.com/')
time.sleep(10)  # Сделаем sleep иначе браузер сразу закроектся перейдя к следующим строкам

# После выполнения необходимых действий, следует явно закрыть браузер
browser.close()

# И остановить Playwright, чтобы освободить ресурсы
playwright.stop()
```

⚠️ Если вдруг 'https://demoqa.com/' прилег, то можете исправить адрес на наш сервис: dev-cinescope.f5qa.ru

### Давайте разберемся что происходит в этом коде:

<aside>
➖

• **`browser = playwright.chromium.launch(headless=False)`** - Здесь мы говорим Playwright запустить браузер Chromium (можно использовать и другие браузеры, такие как Firefox или WebKit).

</aside>

<aside>
➖

**`headless=False`** означает, что браузер будет виден при запуске (если установить **`True`**, браузер запустится в фоновом режиме). Зачем? Когда тесты будут запускаться на серверах, у них нет монитора, чтобы отобразить браузер, из-за чего будет ошибка.
Поэтому локально нам интересно запускать значение False, а на удаленных серверах - True.

</aside>

<aside>
➖

• **`page = browser.new_page()`** - Открываем новую страницу (вкладку) в браузере. Теперь с этой страницей нам и надо взаимодействовать.

</aside>

<aside>
➖

• **`page.goto('https://demoqa.com')`** - Переходим на сайт **`https://demoqa.com`**. Это команда заставляет браузер загрузить указанный URL.

</aside>

<aside>
➖

• **`browser.close()`** - После всех действий закрываем браузер. Это важно, чтобы не оставлять запущенный процесс браузера после завершения скрипта.

</aside>

<aside>
➖

Запустив файл - у нас откроется браузер chrome и перейдет на страницу google.com
После чего скрипт прекратит работу

</aside>

<aside>
❕

• Важно не забывать закрыть браузер с помощью **`browser.close()`** после выполнения необходимых операций

</aside>

<aside>
➖

• В конце, мы вызываем **`playwright.stop()`** для явного завершения сессии Playwright. Это важный шаг, который освобождает ресурсы и предотвращает потенциальные утечки памяти

</aside>

### Базовые понятия в Playwright

> Основные понятия: Browser, Page, Context
> 
> - **Browser**: Представляет собой экземпляр браузера (Chromium, Firefox, WebKit). Это "контейнер" для вкладок (Pages) и имеет методы для управления браузером в целом (запуск, закрытие и т.д.).
> - **Page**: Представляет собой отдельную вкладку или окно в браузере. Именно с Page происходит основное взаимодействие: открытие URL, клики, ввод текста, скроллинг и т.д.
> - **Context**: (Browser Context) Это изолированная среда внутри браузера. Каждый Context может иметь свои настройки (cookies, разрешения, User Agent и т.д.). Contexts позволяют запускать несколько тестов параллельно, не влияя друг на друга. Обычно создается один Context на тест

<aside>
⚙

### Жизненный цикл браузера: запуск, открытие страницы, закрытие

1. **Запуск браузера:** `browser = p.chromium.launch()` (или `p.firefox.launch()`, `p.webkit.launch()`) Запускает выбранный браузер
2. **Создание Context:** `context = browser.new_context()` Создает новый изолированный контекст
3. **Создание Page:** `page = context.new_page()` Открывает новую страницу (вкладку) в Context
4. **Открытие страницы:** `page.goto("url")` Загружает указанный URL в Page
5. **Взаимодействие с элементами:** С помощью методов Page (об этом будет дальше)
6. **Закрытие страницы:** `page.close()` Закрывает текущую Page
7. **Закрытие Context:** `context.close()` Закрывает Context и все связанные с ним Pages
8. **Закрытие браузера:** `browser.close()` Останавливает браузер
</aside>

## Рассмотрим базовые понятия подробнее:

### Browser

<aside>
💭

Как уже говорилось, это "контейнер" для всего.  Представьте себе, что это *приложение* браузера (Chrome, Firefox и т.д.).  Вы запускаете браузер, и получаете объект `Browser`.  Он управляет *всеми* открытыми окнами и вкладками.

</aside>

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()  # Запустили Chrome
    # ... (дальше работаем с browser)
    browser.close()  # Закрыли Chrome
```

<aside>
💡

А значит можно открыть несколько браузеров одновременно.
Для запуска нескольких браузеров одновременно, нужно создать несколько экземпляров класса `Browser`. Каждый экземпляр будет представлять отдельный браузер

</aside>

<aside>
🛠

Вот пример кода, где запускаем Chromium и Firefox одновременно:

</aside>

```python
from playwright.sync_api import sync_playwright
import time

def test_multiple_browsers():
    with sync_playwright() as p:
        chromium_browser = p.chromium.launch(headless=False)
        firefox_browser = p.firefox.launch(headless=False)

        chromium_page = chromium_browser.new_page()
        firefox_page = firefox_browser.new_page()

        chromium_page.goto("https://www.example.com")
        firefox_page.goto("https://www.google.com")

        time.sleep(10)

        chromium_browser.close()
        firefox_browser.close()
```

<aside>
🍄

Попробуйте запустить код выше - вы увидите как откроются 2 браузера. Один - хромиум и другой firefox.

</aside>

### **Page**

<aside>
💡

`Page` в Playwright — это, по сути, *открытая вкладка* или *окно* в браузере. Именно через `Page` происходит основное взаимодействие с веб-сайтом

</aside>

### Создание Page

<aside>
💡

`Page` создается внутри `Context`. Может быть *несколько* `Page` в *одном* `Context` (как несколько вкладок в одном окне браузера).

</aside>

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    context = browser.new_context()
    page1 = context.new_page()  # Первая страница (вкладка)
    page2 = context.new_page()  # Вторая страница (вкладка)

    # ... (работаем с page1 и page2)

    context.close()
    browser.close()
```

### Закрытие Page

> **`page.close()`:** Закрывает *отдельную* страницу (вкладку).Python
> 
> 
> `page1.close()  # Закрыли первую страницу`
> 

### Открытие URL

> **`page.goto("url")`:** Открывает указанный URL в `Page`.Python
> 
> 
> `page1.goto("https://www.example.com")`
>

### Делаем несколько контекстов и пейджей

<aside>
⚙

Давайте разберем пример, где у нас 2 браузера, у каждого по 2 контекста, а в каждом контексте по 2 пейджи

</aside>

```python
from playwright.sync_api import sync_playwright
import time

def test_some_entities():
    with sync_playwright() as p:
        # Запускаем браузер
        browser1 = p.chromium.launch(headless=False)

        # создаем 2 контекста
        context1_1 = browser1.new_context()
        context1_2 = browser1.new_context()

        # В каждом контексте создаем по 2 пейджи
        page1_1_1 = context1_1.new_page()
        page1_1_2 = context1_1.new_page()
        page1_2_1 = context1_2.new_page()
        page1_2_2 = context1_2.new_page()

        # переходим на разные сайты
        page1_1_1.goto("https://www.example.com")
        page1_1_2.goto("https://www.google.com")
        page1_2_1.goto("https://www.wikipedia.org")
        page1_2_2.goto("https://www.yandex.ru")

        # немного ждем чтобы осмотреться
        time.sleep(10)

        # Закрываем пейджи
        page1_1_1.close()
        page1_1_2.close()
        page1_2_1.close()
        page1_2_2.close()

        # Закрываем контексты
        context1_1.close()
        context1_2.close()

        # Закрываем браузер
        browser1.close()
        
```

### Облегчаем себе жизнь при помощи простых фикстур

<aside>
💭

Будем использовать фикстуры `pytest`, чтобы упростить этот процесс инициализации браузера, создания контекста и пейджи. Мы же не хотим тонну кода туда-сюда копировать 🙂

</aside>

### Фикстуры для Browser, Context и Page

<aside>
⚙

Давайте создадим фикстуры для `Browser`, `Context` и `Page`:

</aside>

```python
import pytest
from playwright.sync_api import sync_playwright

DEFAULT_UI_TIMEOUT = 30000  # Пример значения таймаута

@pytest.fixture(scope="session")  # Браузер запускается один раз для всей сессии
def browser(playwright):
    browser = playwright.chromium.launch(headless=True)  # headless=True для CI/CD, headless=False для локальной разработки
    yield browser  # yield возвращает значение фикстуры, выполнение теста продолжится после yield
    browser.close()  # Браузер закрывается после завершения всех тестов

@pytest.fixture(scope="function")  # Контекст создается для каждого теста
def context(browser):
    context = browser.new_context()
    context.tracing.start(screenshots=True, snapshots=True, sources=True)  # Трассировка для отладки
    context.set_default_timeout(DEFAULT_UI_TIMEOUT)  # Установка таймаута по умолчанию
    yield context  # yield возвращает значение фикстуры, выполнение теста продолжится после yield
    context.close()  # Контекст закрывается после завершения теста

@pytest.fixture(scope="function")  # Страница создается для каждого теста
def page(context):
    page = context.new_page()
    yield page  # yield возвращает значение фикстуры, выполнение теста продолжится после yield
    page.close()  # Страница закрывается после завершения теста
```

<aside>
❓

### Как это работает?

1. **`@pytest.fixture(scope="session")`:** Декоратор `scope="session"` указывает, что фикстура `browser` будет создана *один раз* для *всей тестовой сессии*. Это c*экономит нам ресурсы*, так как браузер не нужно запускать и закрывать для каждого теста - здесь изолировать тесты мы будем контекстом
2. **`@pytest.fixture(scope="function")`:** Декоратор `scope="function"` указывает, что фикстуры `context` и `page` будут создаваться *для каждого теста*. Тут мы и получим *изоляцию* между тестами, так как каждый тест будет работать в *своем собственном* контексте и на *своей собственной* странице
3. **`yield`:** Ключевое слово `yield` используется для *возврата значения фикстуры*
    
    Выполнение функции приостанавливается до тех пор, пока тест не завершится. После этого выполнение функции возобновляется, и выполняется код *после* `yield` (закрытие браузера, контекста или страницы)
    
4. `def browser(playwright):` - откуда берется параметр playwright если он не передается? На самом деле когда мы ставили pytest-playwright, то у нас появилась фикстура playwright в стандартном наборе фикстур. Отдельно ее заводить не надо
</aside>

### Использование фикстур в тестах

<aside>
🛠

Теперь мы можем использовать эти фикстуры в наших тестах:

</aside>

```python
def test_example(page):  # page автоматически будет предоставлена фикстурой
    page.goto("https://www.example.com")

def test_google(page):  # page автоматически будет предоставлена фикстурой
    page.goto("https://www.google.com")
```

<aside>
☝

*Более нам не нужно* вручную создавать `Browser`, `Context` или `Page` в тестах. `pytest` *автоматически* предоставит их нам с помощью фикстур

</aside>

<aside>
➕

### Преимущества использования данных фикстур очевидны, но проговорим зачем оно нам:

- Тесты становятся более *короткими* и *легче читаются*
- Код для создания и уничтожения ресурсов *не нужно* писать в каждом тесте - избежали ненужное дублирование кода
- Каждый тест работает в *своем собственном* контексте и на *своей собственной* странице, изолированность есть
</aside>

Как теперь выглядит наш тест:

```python
import time

def test_some_entities(page):
    page.goto('https://demoqa.com')
    time.sleep(10)
```

### Timeout в playwright

<aside>
💭

Управление временем выполнения тестов и предотвращение их зависания нам очень нужно. Для этого в Playwright предусмотрены таймауты, позволяющие задать максимальное время выполнения для теста или отдельного действия

</aside>

### Глобальные таймауты (установка по умолчанию)

<aside>
💡

Глобальные таймауты, устанавливаемые с помощью `context.set_default_timeout()`, действуют на все тесты в рамках данного контекста. Это удобно для установки общего ограничения времени, чтобы тесты не выполнялись слишком долго.

</aside>

```python
DEFAULT_UI_TIMEOUT = 30000  # 30 секунд

@pytest.fixture(scope="function")
def context(browser):
    context = browser.new_context()
    context.set_default_timeout(DEFAULT_UI_TIMEOUT)  # Устанавливаем таймаут по умолчанию для всех действий в контексте
    yield context
    context.close()
```

<aside>
☝

В данном примере `context.set_default_timeout(DEFAULT_UI_TIMEOUT)` устанавливает таймаут по умолчанию равным 30 секундам для всех действий, выполняемых в данном контексте.

</aside>

---

### Локальные таймауты (переопределение для конкретных случаев)

<aside>
⚙

Локальные таймауты позволяют переопределить глобальные для конкретных тестов или действий

Пример, как для метода fill (заполнение инпута текстом) мы устанавливаем timeout. Если в течение этого времени не будет найден элемент, то тест упадет по timeout error

</aside>

```python
    page.fill('input#search', 'Playwright', timeout=5000)
    # Локальный таймаут для заполнения поля
```

---

### Таймаут для теста

<aside>
⚙

Декоратор `@pytest.mark.timeout()` позволяет установить таймаут для конкретного теста.

</aside>

```python
@pytest.mark.timeout(60000)  # Устанавливаем таймаут для теста 60 секунд (1 минута)
def test_long_running_task(page):
    # ... код теста
```

---

### Таймаут для действия

<aside>
⚙

Непосредственно в методы Playwright, выполняющие действия над элементами или страницей, можно передать аргумент `timeout`, чтобы установить таймаут для данного конкретного действия.

</aside>

```python
page.click('button#submit', timeout=10000)  # Кликаем по кнопке, ожидая не более 10 секунд
page.fill('input[name="q"]', 'Playwright', timeout=5000)  # Заполняем поле ввода, ожидая не более 5 секунд
page.goto('https://www.example.com', timeout=60000)  # Переходим по URL, ожидая не более 1 минуты
```

---

### Формат таймаута

<aside>
⚙

Таймаут в Playwright всегда указывается в *миллисекундах*.

- `1000` - 1 секунда
- `5000` - 5 секунд
- `30000` - 30 секунд
- `60000` - 1 минута
</aside>

---

### Когда использовать таймауты?

<aside>
1️⃣

Для ограничения времени выполнения отдельных действий, чтобы тесты не выполнялись слишком долго. Это сигнал о том, что что-то не так с вашим тестом, окружением или подключением

</aside>

<aside>
2️⃣

Для обработки ситуаций, когда элемент может появиться на странице не сразу, а через некоторое время

</aside>

<aside>
3️⃣

Используем глобальные таймауты для установки общих ограничений, а локальные таймауты для обработки особых случаев, когда требуется больше или меньше времени

</aside>

### Пример использования таймаутов для разных случаев

```python
def test_search_product(page):
    page.goto('https://www.example.com')  # Глобальный таймаут (из фикстуры context)

    page.fill('input#search', 'Playwright', timeout=5000)  # Локальный таймаут для заполнения поля

    page.click('button#search-button')  # Глобальный таймаут
```
