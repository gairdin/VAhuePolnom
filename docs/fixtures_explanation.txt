Что такое фикстуры (fixtures) в тестировании?
===============================================

Фикстуры — это механизм подготовки окружения для тестов: создание данных,
настройка соединений, авторизация и т.д. В pytest фикстуры — это функции с
декоратором @pytest.fixture, которые могут переиспользоваться между тестами,
иметь разный "жизненный цикл" (scope) и автоматически внедряться через
аргументы тестовой функции.


Реализация в проекте VAhuePolnom
=================================

Проект тестирует API сервиса Cinescope (auth + movies). Все 9 фикстур
находятся в conftest.py и делятся на уровни:

Scope "session" (создаются 1 раз за сессию тестирования):
----------------------------------------------------------

1. session
   - Создаёт requests.Session() для переиспользования HTTP-соединений
   - Закрывает сессию после всех тестов
   - Зависимости: нет

2. api_manager
   - Инстанцирует ApiManager, который связывает AuthAPI и MoviesAPI
   - Обе клиента используют одну requests.Session, поэтому JWT-токены
     автоматически передаются между запросами
   - Зависимости: session

3. admin_creds
   - Возвращает жёстко заданные учётные данные SUPER_ADMIN
     (email: api1@gmail.com, password: asdqwe123Q)
   - Зависимости: нет

4. existing_movies
   - Делает GET /movies, получает список предзагруженных в БД фильмов
   - Проверяет, что список не пуст
   - Зависимости: api_manager


Scope "function" (создаются заново для каждого теста):
-------------------------------------------------------

5. test_user_data
   - Генерирует уникальные данные регистрации пользователя
     (email с timestamp + случайный суффикс, full name, password)
   - Зависимости: нет

6. movie_data
   - Генерирует уникальные данные фильма
     (имя с timestamp, случайная цена, случайный город MSK/SPB,
      случайный валидный genreId)
   - Зависимости: нет

7. registered_user
   - Регистрирует нового пользователя через POST /register (ожидает 201)
   - Возвращает email и password созданного юзера
   - Зависимости: api_manager, test_user_data

8. existing_movie
   - Берёт первый элемент из списка existing_movies
   - Зависимости: existing_movies

9. created_movie_with_cleanup
   - Аутентифицируется как SUPER_ADMIN
   - Создаёт фильм через POST /movies (ожидает 201)
   - Возвращает тело созданного фильма через yield
   - После завершения теста удаляет фильм через DELETE /movies/{id}
     (это cleanup-фаза)
   - Самая сложная фикстура — реализует setup + teardown
   - Зависимости: api_manager, movie_data, admin_creds


Граф зависимостей фикстур:
===========================

session (session)
  └── api_manager (session)
        ├── registered_user (function)
        │     └── test_user_data (function)
        ├── existing_movies (session)
        │     └── existing_movie (function)
        └── created_movie_with_cleanup (function)
              ├── movie_data (function)
              └── admin_creds (session)

Standalone:
  admin_creds (session)


Что фикстуры дают проекту:
===========================

1. Переиспользование
   - api_manager живёт всю сессию, а не создаётся в каждом тесте заново
   - existing_movies кешируется на всю сессию (session scope)

2. Изоляция тестов
   - Каждый тест получает свежие registered_user и movie_data
   - Тесты не влияют друг на друга через общие данные

3. Автоматический cleanup
   - created_movie_with_cleanup сам удаляет фильм после теста
   - session сама закрывается по завершении

4. Декларативность тестов
   - Тест просто запрашивает нужные фикстуры через аргументы
   - Вся подготовка и уборка скрыта в conftest.py

5. Единая точка входа (ApiManager)
   - Одна фикстура api_manager даёт доступ ко всем API-клиентам
   - Упрощает поддержку: изменения в клиентах не требуют правки тестов


Пример использования в тесте (tests/api/test_movies.py):
=========================================================

    def test_create_movie_as_regular_user_forbidden(
            self, api_manager, registered_user, movie_data
    ):
        api_manager.auth.authenticate(registered_user)
        api_manager.movies.create_movie(movie_data, expected_status=403)

Фикстуры сами регистрируют пользователя, генерируют данные и внедряются
в тест. Тест остаётся декларативным — он только описывает ЧТО проверять,
а не КАК готовить окружение.
